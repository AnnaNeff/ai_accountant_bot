# План разработки AI-Accountant

Этот план описывает последовательность разработки личного бухгалтерского Telegram-бота. Логика этапов идет от надежного минимального учета к AI-распознаванию, документам, налогам, бюджету и защите данных.

Главный принцип разработки:

- Telegram остается только интерфейсом.
- AI извлекает данные и предлагает структуру.
- Учет, налоги, бюджет и отчеты считает детерминированный код.
- Пользователь подтверждает операции перед записью в ledger.

## Этап 1. Каркас проекта

Цель: запустить пустого Telegram-бота.

Сделать:

- создать структуру проекта;
- настроить `.env`;
- добавить Docker и Docker Compose;
- подключить PostgreSQL;
- реализовать базовые команды `/start` и `/help`;
- добавить проверку Telegram `user_id` через allowlist.

Результат: бот запускается, отвечает только разрешенным пользователям, но пока ничего не считает.

## Этап 2. База данных и ручной ввод операций

Цель: сохранять операции без AI.

Сделать:

- создать таблицы `users`, `transactions`, `categories`;
- реализовать команду добавления дохода;
- реализовать команду добавления расхода;
- добавить подтверждение операции перед сохранением;
- добавить просмотр последних операций.

Результат: через Telegram можно вручную вести базовый учет доходов и расходов.

## Этап 3. Стартовые данные и регулярные платежи

Цель: учитывать кредиты, аренду, подписки, регулярные доходы и будущие обязательства.

Сделать:

- добавить шаблон `config/bootstrap.example.yaml`;
- хранить реальный приватный файл как `config/private/bootstrap.yaml`;
- добавить загрузчик стартовых данных;
- создать модель и таблицу recurring rules;
- реализовать job, который создает регулярные операции;
- добавить команду "регулярные платежи".

Результат: бот учитывает не только ручные операции, но и ожидаемые будущие доходы и списания.

## Этап 4. AI-распознавание текста

Цель: пользователь пишет обычной фразой, а бот сам предлагает черновик операции.

Сделать:

- добавить LLM client;
- подготовить prompt для извлечения структурированного JSON;
- реализовать validation layer;
- добавить confidence score;
- показывать пользователю подтверждение перед сохранением.

Результат: фраза вроде "Заплатила 120 шекелей за интернет" превращается в предложенную расходную операцию, которую пользователь может подтвердить, изменить или отменить.

## Этап 5. Фото чеков и OCR

Цель: принимать фото чеков, счетов и квитанций.

Сделать:

- реализовать загрузку фото из Telegram;
- сохранять документы в локальное приватное хранилище;
- считать hash файла;
- добавить OCR;
- передавать OCR-текст и/или изображение в AI Extractor;
- связывать документ с операцией.

Результат: пользователь отправляет чек, бот распознает данные и предлагает готовую операцию для подтверждения.

## Этап 6. Базовый налоговый модуль

Цель: считать предварительные налоговые резервы.

Сделать:

- реализовать VAT calculator;
- реализовать income tax reserve calculator;
- реализовать Bituach Leumi estimator;
- добавить модель `tax_period`;
- добавить налоговый конфиг, например `config/tax_rules/israel_2026.yaml`;
- реализовать отчет "налоги сейчас".

Результат: бот показывает, сколько примерно надо отложить на VAT, подоходный налог и Bituach Leumi.

Важно: налоговые правила должны храниться в отдельном конфигурационном слое и обновляться при изменении законодательства. LLM не должен самостоятельно "придумывать" налоговый расчет.

## Этап 7. Бюджетный модуль

Цель: отвечать на вопросы вроде "сколько можно потратить на этой неделе".

Сделать:

- рассчитать текущий свободный баланс;
- учесть ожидаемые поступления;
- учесть будущие регулярные платежи;
- учесть налоговые резервы;
- добавить недельный и месячный бюджет;
- добавить safety buffer;
- предупреждать о риске кассового разрыва.

Результат: бот дает практическую цифру, сколько можно безопасно потратить за неделю или месяц.

## Этап 8. Отчеты

Цель: получать понятные отчеты по бизнесу, налогам и документам.

Сделать:

- отчет за месяц;
- отчет за квартал;
- отчет за год;
- отчет по категориям;
- отчет по VAT;
- отчет по прибыли;
- cashflow-отчет;
- экспорт CSV/XLSX;
- список операций без документов;
- список неподтвержденных операций.

Результат: бот становится полезным как личный бухгалтерский помощник и источник отчетности.

## Этап 9. Защита, бэкапы, аудит

Цель: не потерять данные и не раскрыть личную финансовую информацию.

Сделать:

- настроить encrypted backups;
- добавить restore script;
- реализовать audit log для изменений;
- использовать soft delete вместо физического удаления;
- усилить ограничение доступа;
- логировать ошибки без персональных данных;
- проверить, что AI не получает лишнюю финансовую историю.

Результат: проект можно безопасно использовать лично.

## MVP-порядок

Минимальную полезную версию лучше собирать в таком порядке:

1. Telegram bot.
2. PostgreSQL.
3. Ручной ввод доходов и расходов.
4. Стартовые данные и регулярные платежи.
5. Простой отчет за месяц.
6. Простой расчет свободных денег.
7. AI для текста.
8. Фото чеков.
9. Более сложные налоги.

Такой порядок позволяет быстро получить работающий продукт и не застрять на сложной архитектуре до появления базовой пользы.
